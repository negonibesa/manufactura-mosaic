Разобрался — в файле реально сохранилась работающая архитектура (два режима: corridor и tiles, camModeBlend для плавного перехода), но в коде есть два конкретных места, из-за которых обратный переход (плитки → коридор) ломается, а не «прямой», где всё гладко. Покажу построчно.

Баг №1 — камера при возврате не плавная, а мгновенная (это и есть «потерял ракурс»)

В функции update(), там, где обрабатывается смена режима камеры:

js
if (mode === 'tiles') {
  camera.position.x += (0 - camera.position.x) * (1 - Math.exp(-dt * 2.2));
  camera.position.y += (CAM_TILES_Y - camera.position.y) * (1 - Math.exp(-dt * 2.2));
  camera.position.z += (CAM_TILES_Z - camera.position.z) * (1 - Math.exp(-dt * 2.2));
  camera.lookAt(0, ribbonMid, LENTA_Z);
} else {
  camera.position.z = z;        // ← мгновенно, без сглаживания
  camera.position.y = 1.7;      // ← мгновенно
  camera.rotation.set(0, 0, 0); // ← мгновенно, стирает поворот от lookAt()
}

В сторону «плитки» камера едет плавно (экспоненциальное сглаживание, 1 - Math.exp(-dt * 2.2)). В сторону «коридор» — позиция и поворот выставляются жёстко за один кадр. Именно этот camera.rotation.set(0,0,0) мгновенно стирает угол, заданный через lookAt(), и это выглядит как «дёрг» ракурса, который вы описали.

Баг №2 — карточки при возврате «замерзают», а не едут обратно

Карточки в режиме плиток позиционируются так (в цикле по каждой карточке):

js
if (mode === 'tiles' && !focusing && !focusCard) {
  const s = tilePos(card.index, camModeBlend);
  x += (s.x - x) * camModeBlend;
  y += ((s.y + lift) - y) * camModeBlend;
  ...
}

Тут две проблемы разом:

Весь блок завязан на mode === 'tiles', а не на camModeBlend > 0. Как только вы переключаете обратно на «Коридор», mode меняется мгновенно (в setMode()), и это условие сразу перестаёт выполняться — блок просто не запускается ни на одном кадре после клика, сколько бы ни длилось затухание camModeBlend. Карточки в этот же кадр падают в дефолтные x = card.x, y = card.y — мгновенный снэп, без единого промежуточного кадра.
Даже если бы условие было верным, сама формула x += (s.x - x) * camModeBlend — это не «доля пути от А до Б», а шаг сглаживания за кадр. Когда camModeBlend уменьшается к нулю (обратный ход), шаг тоже уменьшается почти до нуля — то есть карточка не едет назад к коридорной позиции, а просто останавливается там, где была.

Как чинить, коротко:

В else-ветке камеры — заменить жёсткое присваивание на такое же экспоненциальное сглаживание, как в ветке tiles (к y = 1.7, к z, и rotation затухать до (0,0,0) через *= Math.exp(-dt * 2.2), а не .set(0,0,0)).
Условие mode === 'tiles' в блоке позиционирования карточек заменить на camModeBlend > 0.001 — тогда блок продолжит выполняться и во время обратного затухания.
Саму формулу интерполяции поменять с «шаг за кадр» на честную интерполяцию между двумя фиксированными точками: x = card.x + (s.x - card.x) * camModeBlend (не x +=, а прямое присваивание от базовой коридорной позиции к целевой позиции на ленте) — тогда при camModeBlend → 0 карточка гарантированно возвращается в card.x, а не застревает.
